# Linux SSH Brute Force Investigation Using Splunk SIEM

## Executive Summary

A Security Information and Event Management (SIEM) alert was generated following suspicious SSH authentication activity on a Linux server. The alert indicated a potential brute-force attack targeting multiple user accounts from a single external IP address. Using Splunk Enterprise, Linux authentication logs were analyzed to validate the alert, determine the scope of the attack, identify successful authentication attempts, and investigate any post-compromise activity.

The investigation confirmed that the attacker successfully compromised a valid user account after numerous failed login attempts, escalated privileges to the root account, and established persistence by creating a new local user account. Based on the collected evidence, the alert was classified as a **True Positive**.

Filtering only failed authentication events revealed that the account **john.smith** experienced **500 failed login attempts** from the same source IP address (**10.10.242.248**). The consistent attack source and high volume of failed attempts confirmed an SSH brute-force attack.

# SOC Assessment

Analysis of the Linux authentication logs confirmed that the alert represented a genuine security incident. The attacker performed a sustained SSH brute-force attack against the Linux host, successfully authenticated to the **john.smith** account, escalated privileges to **root**, and created a new local account (**system-utm**) to maintain persistence. These activities demonstrate multiple stages of the attack lifecycle and require immediate containment to prevent further compromise.

---

# Recommended Response Actions

- Immediately disable or remove the **system-utm** account.
- Reset credentials for all affected user accounts, particularly **john.smith**.
- Review all privileged sessions initiated during the incident.
- Block the malicious source IP (**10.10.242.248**) at network and host-based security controls.
- Enable account lockout policies to reduce the effectiveness of brute-force attacks.
- Implement multi-factor authentication (MFA) for SSH access.
- Review additional authentication logs to identify any lateral movement or further malicious activity.

---

# Lessons Learned

This investigation demonstrated the importance of correlating authentication logs within Splunk to validate SIEM alerts. By combining failed login analysis, session tracking, and account management events, it was possible to reconstruct the complete attack sequence—from brute-force authentication through privilege escalation and persistence. This workflow reflects a typical Tier 1 SOC investigation and highlights the value of structured log analysis during incident response.
